# FocusMask 1.0.0 — release design

Nothing is published yet, so every fix and feature below ships as **1.0.0** (no version bump).

## Intent

Ship a clean first store release: fix the bugs found in review, add the break
transition countdown, then hand over a store-ready package plus every listing
field ready to paste into the Chrome Web Store developer console.

## Goals

### 1. Bug fixes
1. **Media session stuck "playing" after a superseded play.** `Player.play()` must report
   whether it actually started (e.g. return `false` when the load token was superseded);
   `offscreen/main.ts` only calls `session.setPlaying(true)` when it did.
2. **Sleep timer while paused.** Choosing a sleep timer while paused also starts playback
   (same path as `play`, so it overrides auto-pause / ends a break like a play press).
3. **Options "Custom" chip** re-derives from `value` when the value changes elsewhere
   (and isn't one of the presets).
4. **Popup volume slider** follows `settings.volume` changes from elsewhere while the user
   isn't dragging.
5. **`onInstalled` → `saveSettings({})`** runs inside `serial()`.

### 2. Improvements
- **Gapless custom sounds:** files ≤ ~3 min are decoded with `decodeAudioData` into an
  `AudioBuffer` and looped like built-ins; longer files keep the `<audio loop>` path
  (memory bound). Decoded custom buffers share the existing LRU cache (`MAX_CACHED`).
- **Shared status labels:** one `statusLabel(kind, variant)` helper used by popup,
  options NowPlaying and badge; one shared custom-name lookup.
- **Custom sleep timer value** in the popup (1 min – 12 h, matches `SLEEP_LIMITS`).
- **Volume message throttling:** popup sends live volume at most once per animation frame.
- **Metadata-only lookups** in the worker (`resolveSoundId`, `soundName`) — use a
  cursor/key check rather than reading the full record.
- **Worker unit tests:** extract orchestration from `background/index.ts` so it can be
  tested against a Chrome API mock (alarms, storage, offscreen messaging).
- **Cleanup:** remove `void changes`, unused `AudibleDebouncer.force()`; bump `lucide-react`
  to 1.77. TypeScript 7 stays out.

### 3. Breaks in the popup
- Break length choice in the popup (same presets + custom as options).
- During a break: existing **End break & resume**.
- Outside a break (breaks on): **Restart** next to "Next break in …" — resets the
  countdown to the full interval. *(My reading of "user should be able to restart";
  correct me if you meant something else.)*
- Already true, unchanged: when a break ends (timer, snooze, skip, end early) the
  next-break countdown restarts automatically.

### 4. Break transition countdown (option A)
Applies **only to break start (auto-pause) and break end (auto-resume)** — never to
tab auto-pause, screen lock, sleep timer or manual actions.

- **When:** 5 s before a break starts, *if the sound is playing*; 5 s before a break
  ends, *if the sound will resume* (the break is the only pause reason). Otherwise no
  countdown and no chime (the break notification still shows as today).
- **What the user gets:**
  - A chime at the start of the countdown — a descending two-note tone before a pause,
    ascending before a resume. Synthesized in the offscreen doc (no audio files),
    level tied to the user's volume.
  - Toolbar badge shows `5 … 1`, tooltip "Break in 5s" / "Resuming in 5s".
  - Popup status: "Pausing for a break in 4s" / "Resuming in 3s".
- **Mechanics:** a warning alarm at `T − 5 s` next to the existing break-start /
  break-end alarms; the existing alarm at `T` stays authoritative for the actual
  transition. New `RuntimeState.countdown: { kind: 'pause' | 'resume'; at: number } | null`.
  Badge ticks via a 1 s timer in the worker during the 5 s window.
- **Cancellation:** manual pause/play, End break, Snooze/Skip, breaks toggled off,
  or interval/length changes clear the countdown and its warning alarm.
- **Reconcile:** on worker wake, recreate a missing warning alarm if > 5 s remain;
  drop a stale countdown whose `at` has passed.
- No new setting to switch the chime off (not requested). Easy to add later.

## Non-goals
- Pausing the break clock while the screen is locked (explicitly kept as is).
- Countdown or chime for tab auto-pause, screen lock or sleep timer.
- TypeScript 7 migration.
- Automating the dev console (no browser access; the Web Store API can upload a package
  but can't fill listing or privacy fields).

## Approaches considered for the countdown
- **A. Breaks only (chosen):** scheduled, so the countdown starts early and adds no delay.
- B. Breaks + every auto-resume: rejected (not wanted).
- C. Everything including tab auto-pause: rejected — 5 s of noise over the start of every call/video.

## Verification
`npm run typecheck`, `npm test`, `npm run test:e2e` all green. Add e2e cases for the
countdown (badge digits, chime played → offscreen status, cancel on manual pause) and
popup break controls. Then `npm run release`.
