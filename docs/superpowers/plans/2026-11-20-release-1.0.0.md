# FocusMask 1.0.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the review bugs, add a 5 s countdown + chime around break transitions, add popup break controls, build the `focusmask.bhaggat.in` landing site, and produce a store-ready 1.0.0 package with every listing field final.

**Architecture:** MV3 extension — service worker (`src/background/`) owns state via a pure reducer (`src/shared/state.ts`) and drives an offscreen audio document (`src/offscreen/`); popup/options are React views over `chrome.storage.session`. The countdown adds a warning alarm 5 s before each break alarm; the existing alarm stays authoritative. The landing site is plain static HTML in `site/`, assembled by `scripts/site.mjs` and deployed by GitHub Pages.

**Tech Stack:** TypeScript 5.9, React 19, Vite 8, Vitest 5 (jsdom + fake-indexeddb), Playwright 1.65, Web Audio, GitHub Actions Pages.

**Spec:** `docs/superpowers/specs/2026-11-20-release-1.0.0-design.md`

## Global Constraints

- Version stays `1.0.0` in `package.json` and `public/manifest.json`.
- No new manifest permissions; no remote code, `eval` or `new Function` (enforced by `scripts/zip.mjs`).
- Countdown + chime apply **only** to break start (auto-pause) and break end (auto-resume). Never tab auto-pause, screen lock, sleep timer, or manual actions.
- Countdown length: `COUNTDOWN_MS = 5000`.
- Breaks keep running on the wall clock while the screen is locked (no change).
- Landing site: `https://focusmask.bhaggat.in`; privacy policy `https://focusmask.bhaggat.in/privacy-policy`; support `https://focusmask.bhaggat.in/support/`; contact `dhruvbhagat98@gmail.com`. No trackers or third-party scripts.
- **Do not `git commit` or `git push`.** The user commits on request. Each task ends with a checkpoint (tests green), not a commit.
- Every task: `npm run typecheck` and `npm test` green before moving on. E2E (`npm run test:e2e`) at the end of Tasks 4, 5, 6 and 8.

## Review Focus

1. **Interval/length changed or breaks toggled off during the 5 s window** → countdown and both warn alarms cleared, no stale break starts. Test: Task 5 e2e `countdown is cancelled by settings change`.
2. **Worker killed mid-countdown** (Chrome idles it; `countdown.at` already passed on wake) → stale countdown cleared, badge back to normal. Test: Task 5 e2e step with `restartWorker`.
3. **Break ends while the user is manually paused or the screen is locked** → no resume chime, no countdown. Test: Task 5 unit `shouldCountdown`.
4. **Break alarm at `T` fires late or not at all** → the ticker's own timeout still performs the transition, once. Test: Task 5 unit `CountdownTicker calls onDone once at at`.
5. **Custom file with unknown duration (0) or longer than 3 min** → plays via `<audio loop>`, never decoded into memory. Test: Task 4 unit `loopModeFor`.
